# UNEC Students Hub v1.1.25

Automatic PDF-based practice, AI-assisted written exams, Cloudflare-backed study plans for 25 majors, and a redesigned Premium experience.

This release brings together the website updates since v1.1.23, including material imports, curriculum improvements, profile selectors, payment guidance and server-enforced Free/Premium allowances.

## ✨ What's new

### 📝 One Practice section, two consistent formats

- Renamed the section to **Practice / Sınaq**. The Azerbaijani format titles are **Elektron-Test tipli Sınaq** and **Elektron-Yazılı tipli sınaq**.
- Unified the setup cards, allowance indicators, subject/PDF selectors, choice buttons and start buttons around the Electronic Test design. Written-exam requirements and AI grading details are available in an expandable information section.
- **Sign-in is required for both formats.** Completed results are recorded in the user's Dashboard; account changes clear the previous account's active browser practice state.
- Kept separate daily allowances for Electronic Test, Electronic Written and private PDF uploads. Started or abandoned exams count toward the relevant allowance; selecting a subject or reading a public PDF does not.

### 📄 Automatic Electronic Test questions from PDFs

- Discover eligible electronic-test materials directly from **`pdfs.js`**, replacing the separate manually maintained question selection. A PDF can override its subject's format, allowing written and multiple-choice materials under the same subject.
- Select the **most recently added PDF by default**, using its catalogue addition date. Users can choose a different source before starting; questions from different PDFs are not mixed into one selected-source exam.
- Read numbered questions, multiline options, supported answer marks, explicit letter answer keys and vector radio-button selections exported inside PDFs. Numeric answer text is preserved.
- Merge exact duplicates within the selected PDF and exclude conflicting or ambiguous answer keys. The parser never assumes that the first answer is correct.
- Retain question-count selection, timers, result review and links back to source material. Distinguish download failures from PDFs with no eligible questions, with controls to retry.
- Cache public parsed questions locally for seven days, with versioned keys and a memory fallback. Only selected PDFs are fetched; entering Practice does not download the full library.
- Scans, unreadable text, unsupported image-based questions and unmarked answers are not guessed into scored questions.

### ✍️ AI-assisted Electronic Written practice — beta

| Mode | Questions | Points per question | Maximum score | Time per question |
|---|---:|---:|---:|---:|
| Midterm | 3 | 10 | 30 | 20 minutes |
| Semester | 5 | 10 | 50 | 20 minutes |

- Randomly select questions from the chosen electronic-written PDF. The newest written material is selected initially, and the user can change it.
- Compare the student's own answers against reference explanations extracted from that PDF using the configured Groq service.
- Enforce deadlines on the server. Moving to the next question locks the preceding answer; closing the page does not pause the exam clock.
- Save answers and browser drafts, support resuming recent exams, and retry interrupted grading without consuming a new exam slot.
- Return per-question scores, feedback, missing points and relevant source excerpts. Blank answers receive zero; an answer that cannot be reliably graded remains explicitly ungraded instead of receiving a fabricated score.
- Save completed written results idempotently to Dashboard, including retrying a failed history write without grading the same exam again.
- AI scores are for practice and are **not official university grades**. Written sources need readable numbered questions and reference explanations; question-only or unsupported scanned PDFs cannot serve as grading references.

### 📥 Practice with private PDFs

- Signed-in users can upload their own PDFs, up to **3 MB per file**, for eligible multiple-choice questions or written questions with reference answers.
- Allow **1 successful import per day on Free** and **3 on active Premium**. Unsupported parsing does not spend a successful import; retrying the same successful request does not charge another slot.
- Add a selector for multiple uploaded PDFs so users can return to an earlier source after another upload.
- Keep earlier sources available for their existing exams. Owner-bound source IDs, concurrency checks and parser leases prevent another upload from overwriting a newer or already-used source.
- Store extracted questions and explanations privately, not the original PDF bytes. Sources do not enter the public catalogue, and private PDF filenames are excluded from quiz analytics.
- Bound retained extracted data to six alternating storage slots, with current/previous-day access and compatibility for older source IDs. Private data remains included in account export and deletion.

### ⭐ Free and Premium allowances

| Feature | Free | Active Premium |
|---|---:|---:|
| AI questions | 5 per day | 12 per day |
| AI message length | 250 characters | 400 characters |
| Electronic Test exams | 5 per day | **10 per day** |
| Electronic Written exams | 3 per day | **5 per day** |
| Private PDF uploads | 1 per day | **3 per day** |

- Every Premium duration has the same allowances; only the duration differs.
- Resolve Premium access on the server from **redeemed activation-code receipts**, not browser flags or editable profile fields.
- Preserve the current day's usage through upgrades and expiry. Daily allowances reset at **midnight in Baku**.
- Refresh practice/upload allowances after successful code activation without requiring a page reload. Expired Premium uses the Free allowance while retaining already consumed usage and access to retained private sources.
- Protect start/import limits against concurrent requests and duplicate retries. Receipt lookup failures do not silently grant an allowance.

## 🛠️ Maintenance and catalogue publishing

- Keep `pdfs.js` as the editable material catalogue. Main files must exist under the configured Cloudflare **`pdf/`** path; extras use **`pdf-extra/`**.
- After catalogue changes, run `python tools/sync-material-dates.py` and `node tools/build-site.mjs`, then commit generated changes along with the catalogue. The build updates public pages, trusted practice-source lists, the sitemap and offline assets; adding a filename alone does not update the deployed server allowlists.
- Preserve verified historical dates and legacy identity mappings when editing or moving materials. Refresh asset versions so browsers receive the updated interface.
- Document the new practice modes, private-source retention, account behavior and payment process in the README and service setup guide.

## 🚀 Deployment

Frontend and backend changes use the existing GitHub Pages and Vercel setup. The backend uses **Node.js 24** and the pinned **`unpdf` 2.1.0** dependency; install backend dependencies with `npm ci --prefix ai-vercel`.

AI written grading requires the existing Firebase service-account configuration and `GROQ_API_KEY`. `WRITTEN_EXAM_MODEL` optionally selects a supported Groq model. Provider availability can temporarily pause grading; saved answers and grading retries remain available. Premium allowance and QR/email changes require no additional payment API key or public Firestore permissions.
